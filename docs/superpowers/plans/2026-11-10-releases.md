# QuestChain Releases Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this approved plan in the current session.

**Goal:** Publish identifiable, installable QuestChain releases for CurseForge and GitHub-based addon managers.

**Architecture:** Keep the numeric source TOC version and require matching Git tags. Use BigWigs packager to stamp the packaged version, create the ZIP and changelog, declare dependencies, and publish release metadata. Ordinary branch builds remain unpublished artifacts.

**Tech Stack:** GitHub Actions, BigWigs packager, Bash, Python standard-library integration tests, Lua 5.1 fixtures.

**Spec:** The release recommendation approved in this conversation on 2026-11-10.

## Global Constraints

- Display name QuestChain; addon folder and TOC basename ForeverQuestChain.
- Forever interface 16001; QuestieDB required; TomTom optional.
- Preserve and exclude pre-existing local UI edits from this commit.
- Work on main and push as explicitly requested.
- Publish stable tags; never publish branch builds to addon hosts.
- Refuse mismatched versions and pre-existing GitHub releases; do not silently replace releases.

## Review Focus

- Nested addon source must produce one installable top-level folder.
- The packaged TOC version must identify the same build as the ZIP filename.
- Missing publishing credentials must fail tagged releases before uploading.
- A publication retry must not blindly duplicate an accepted CurseForge upload.
- Development builds must remain available as artifacts without publishing credentials.
