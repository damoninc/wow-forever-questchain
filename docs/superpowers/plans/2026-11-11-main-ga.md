# Direct main-to-GA pipeline

**Approved requirement:** Every merge/push to main automatically publishes a stable addon release. One merged source commit, one package, and the same ZIP for GitHub and CurseForge. Keep BigWigs. No release button or manual TOC bump.

**Cause of the previous mismatch:** Main CI did not deploy; a separate manual workflow created a version commit and rebuilt before publication.

**Implementation:**

- Replace the two workflows with one CI/deploy workflow triggered by pull requests and main pushes.
- PRs run checks; successful main pushes automatically allocate the next stable patch tag on the merged commit itself.
- Use the tag as the version source; the committed TOC has BigWigs' project-version substitution token. Remove manual version-bump helpers and workflow.
- Queue main releases instead of cancelling them. Test first, then run BigWigs once with both publication credentials.
- Keep single-attempt CurseForge uploads. Retain its file ID, ZIP name and checksum as a deployment receipt.
- Verify GitHub's downloaded ZIP matches the file sent to CurseForge, along with the stable channel and Forever manifest.
- Reruns must not silently re-upload an uncertain accepted CurseForge POST or replace a completed release.

**Checks:**

- Version allocation: existing stable tag, ignored prereleases, next patch, initial stable version, and retry identity.
- Real BigWigs fixture packages: shipped folder and files, version substitution, required dependency, and one-attempt upload behavior.
- Five Lua suites, workflow validation, independent read-only review, then push main and observe actual publication to both hosts.

**Release boundary:** CurseForge can moderate/index an accepted file after upload. Pipeline success must report its actual file ID and stable release type.

**Verified locally:** Six version/order checks, five real packaging/upload checks, and all five Lua suites pass. The successful localhost upload test checks the receipt hash against the multipart ZIP bytes received by the server. Review caught and tests now prevent allocating a newer version for older source after a newer merge is released. Actionlint passes with only its outdated schema's queue-key diagnostic excluded; GitHub's current documented queue:max syntax is retained so pending main releases are not replaced.
